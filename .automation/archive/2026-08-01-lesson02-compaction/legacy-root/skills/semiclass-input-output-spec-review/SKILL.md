# 입·출력 규격 검증

## 언제 쓰나요

`workflow/WORKFLOW.md`를 처음 시험하기 전, 또는 실행 결과가 기대와 달랐을 때 사용합니다.

## 먼저 읽을 자료

1. `design/automation-blueprint.md`
2. `progress/roadmap.md`
3. `workflow/WORKFLOW.md`
4. `01-input/`의 현재 입력 예시
5. `02-reference/`의 승인된 입력·출력 기준
6. 이미 있다면 `tests/`의 실행 기록

## 검토 순서

1. 자동화 타겟을 `트리거 → 허용 입력 → 처리 경계 → 결과물 → 사람 확인 → 완료 증거` 한 줄로 적습니다.
2. 입력의 형식, 필수·선택 항목, 출처, 정규화, 민감정보 경계, 누락·오류 때의 행동을 표로 확인합니다.
3. 출력의 파일 또는 메시지, 필수 제목·열, 허용 값, 근거, `확인 필요` 표기, 사람 검토, 완료 증거를 표로 확인합니다.
4. 입력에는 없는데 출력이 요구하는 값, 이름·상태·저장 위치가 서로 다른 곳, 실제 생길 수 있는 예외를 찾습니다.
5. 가장 중요한 미결 예외 **하나만** 수강생에게 묻습니다. 선택지는 `허용 규칙 추가`, `정보 요청`, `실행 중단`, `사람 검토 대기`입니다.

## 지켜야 할 경계

- 자료에 없는 사실을 채우지 말고 `확인 필요`로 둡니다.
- 같은 원본을 이미 처리한 기록이 있으면 중복 입력으로 중단합니다. 새 결과·연결 초안·외부 행동·정상 완료 기록을 만들지 않습니다.
- 수강생의 답과 승인 전에는 워크플로우를 고치지 않습니다. 승인 뒤에도 before/after와 다음 시험 케이스를 보이는 최소 수정만 제안합니다.
- 실제 발송·저장·삭제·결제·권한 변경은 하지 않습니다.

## 다음 행동

규격이 정해졌는데 시험할 입력이 부족하면 `$semiclass-mock-input-generator`를 사용합니다. 입력을 처리한 실제 결과는 이 지침으로 다시 검토합니다.
