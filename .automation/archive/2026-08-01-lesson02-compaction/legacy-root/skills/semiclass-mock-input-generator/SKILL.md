# 목 입력 생성

## 언제 쓰나요

승인된 입력·출력 규격을 여러 상황에서 시험하고 싶을 때 사용합니다. 실제 익명 입력을 실행할 수 있다면 목 입력은 필수가 아니라 보조 시험 방법입니다.

## 먼저 읽을 자료

1. `design/automation-blueprint.md`
2. `workflow/WORKFLOW.md`
3. `02-reference/`의 승인된 입력·출력 규격
4. 이미 있다면 `01-input/`의 예시와 `tests/`의 이전 기록

규격이 비어 있거나 서로 맞지 않으면 데이터를 지어내지 말고, 필요한 규칙을 한 가지 질문으로 확인합니다.

## 만들 네 가지 케이스

- `N-01`: 필수 값이 모두 있는 정상 입력
- `N-02`: 의미는 같지만 표현·순서·형식이 다른 정상 입력
- `E-01`: 필수 값 하나가 빠졌거나 형식이 틀린 입력
- `E-02`: N-01과 같은 원본을 두 번째로 제출한 중복 입력

현재 워크플로우의 입력 형식을 보존합니다. 이메일은 제목·본문·첨부 여부, 스프레드시트는 헤더·행 ID·형식, 대화는 발화자와 순서, 폼·프롬프트는 질문·답변·빈 값을 보존합니다. 모든 이름·회사·날짜·값은 가상 값으로 바꾸고, 실제 인물·회사·개인정보·비밀값은 넣지 않습니다.

## 매니페스트에 적을 것

각 케이스의 안정적인 ID, 파일 이름 또는 행 위치, 시험 목적, 적용 규격, 기대 행동, 확인할 출력 의무, 금지 행동을 `tests/`에 남깁니다.

- N-01·N-02는 표준 산출물의 형식이 같은지 확인합니다.
- E-01은 질문·`확인 필요`·중단·초안만 생성 중 승인된 행동을 확인합니다.
- E-02는 반드시 중단합니다. 새 결과·Slack 초안·외부 행동·정상 완료 기록을 만들지 않습니다.

## 다음 행동

각 입력을 처리한 실제 결과와 매니페스트를 **입·출력 규격 검증**
(`$semiclass-input-output-spec-review`)에 다시 넣어, 출력 규격과 안전한 중단이 지켜졌는지 검토합니다.
