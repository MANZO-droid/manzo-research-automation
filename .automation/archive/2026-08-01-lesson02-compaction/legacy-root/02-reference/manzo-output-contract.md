# 만조리서치 Top10 종목 분석 — 출력 규격 (코드 기준, 2026-07-25 확인 → 재확인)

`scripts/collect_gainers.py`의 `analyze_stock()`이 실제로 요구·생성하는 값을 그대로 옮긴 기준입니다.
"정답"이 아니라 검토 기준이며, 코드가 바뀌면 이 문서도 다시 확인해야 합니다.

이 파일은 한 번, 로컬에서 krx_calendar 연동이 빠진 채로 되돌려져 있던 `collect_gainers.py` 버전을
기준으로 작성됐다가, 커밋된 정상 버전으로 복원한 뒤 다시 확인해 고쳤습니다(`AUTOMATION_NOTES.md`,
`design/automation-blueprint.md` 참고).

## 뉴스가 0건일 때

`analyze_stock()`은 뉴스 기사를 하나도 못 찾으면 **Gemini를 아예 호출하지 않고** 곧바로
`riseReason`에 "OO에 대한 뉴스 기사를 수집하지 못했습니다."라는 안내 문구만 넣고 `chartAnalysis`는
빈 문자열로 반환합니다. 뉴스가 없다고 Gemini가 추정해서 지어내는 동작은 없습니다.

## 뉴스가 1건 이상일 때 — Gemini에게 실제로 전달되는 입력

- 종목명, 종목코드, 날짜, 당일/주간 상승률(%)
- 수집된 뉴스 기사(최대 15개, `title`+`summary`)
- 실제 계산된 `technicals`(ma5/ma20/ma60/ma120/현재가/52주고가·저가/고가·저가대비%/거래량비율/추세/골든·데드크로스 발생 여부) — **2026-07-25 수정으로 추가됨.** 이전에는 이 값이 프롬프트에 전달되지 않아 `chartAnalysis`가 실제 계산값과 다른 크로스 상태를 서술하는 사례가 다수 있었음(아래 사람 검토 체크리스트 참고)
- **전달되지 않는 것**: `ohlcv`(일별 시세 원자료), `financials`

## 출력 필드와 최소 분량

| 필드 | 최소 분량 | 근거 |
| --- | --- | --- |
| `riseReason` | 200자 이상 | 프롬프트 지시 "200자 이상" |
| `chartAnalysis` | 150자 이상 | 프롬프트 지시 "150자 이상으로 작성" |

지시: "기사에서 확인된 핵심 급등 원인만 서술, 추측 금지, 구체적 수치는 반드시 포함, 기사에 없는
사건(공시 종류·계약 상대방·날짜·금액 등)은 지어내지 말 것"(2026-07-25 추가).

## 사람 검토 체크리스트

- **사실관계**: `riseReason`에 적힌 근거(계약·수주·이슈 등)가 실제로 수집된 기사 제목/요약에 있는가? 기사에 없는 사실이 섞여 있지 않은가? (실제 사례 있음: 기가레인 2026-07-13, 기사 5건에 없는 "조회공시" 언급 — `tests/manzo-regression-2026-07-13.md`)
- **수치 일치**: `chartAnalysis`가 묘사하는 이동평균 배열·골든/데드크로스·거래량 상태가 같은 항목의 `technicals` 실제 값과 맞는가? (2026-07-25 이전 데이터는 전체 120건 중 크로스 언급 10건 중 7건이 불일치 — 코드 수정 이후 실행분부터 재확인 필요)
- **분량**: `riseReason` 200자 이상, `chartAnalysis` 150자 이상인가? (로드맵의 "250자 이상"과는 기준이 다름 — 어느 쪽을 기준으로 할지 확인 필요)
- **필터링**: 우선주·관리종목·ETF·정리매매 종목이 Top10에 섞여 있지 않은가? (현재 코드에 자동 필터링이 없어 사람이 직접 확인해야 함)
- **빈 값**: `news`가 0건인데 `riseReason`이 뉴스 없음 안내 문구가 아니라 단정적인 분석 문장으로 채워져 있지 않은가? `financials`가 `{}`인데 화면에 재무 수치인 것처럼 보이지 않는가?
