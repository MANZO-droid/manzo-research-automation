AI 업무자동화 2강 공통 실습 팩

목적
개인 업무 자료가 없거나 실제 API·데이터 연결이 아직 안 되어 있을 때, 당일 상승률 상위 종목 원시
자료 두 건을 같은 기준으로 처리합니다. 자동화 흐름은 `당일 Top10 원시 자료 → Top10 정리와 상승 이유
요약 → 게시 초안 → 사람 검토(게시 이후 사후 검토)`입니다. 모든 종목명·수치·뉴스 문구는 수업용 가상
정보입니다.

이 폴더는 2강 시작 패키지에 함께 들어 있는 공통 샘플입니다. 이 폴더만 따로 프로젝트로 열지 마세요.

1. 별도의 샘플 ZIP은 받지 않습니다. `2강 시작 패키지 ZIP`을
   `업무자동화/강의자료/`에 압축 해제하면 이 폴더가 함께 생깁니다.
2. 상위 `업무자동화/`에서 먼저 `강의자료/README.md`의 한 문장을 실행해 공용 작업 폴더를 설정합니다.
   설정 과정에서 이 폴더의 N-01·N-02는 `업무자동화/01-input/`으로, output-contract.txt는
   `업무자동화/02-reference/`로 복사됩니다. 이 폴더의 원본은 보존합니다.
3. 개인 1강 로드맵 파일이 전혀 없을 때만 `virtual-lesson-01-roadmap.html`을
   `업무자동화/progress/roadmap.html`로 **그대로 복사**합니다. 이 파일은 1강 가상 산출물의
   검증된 화면이므로 새로 만들거나 내용을 바꾸지 않습니다. `virtual-lesson-01-roadmap.md`는
   같은 가상 실습의 텍스트 참고용입니다.
4. 슬라이드 15에서 `01-input/`의 정상 입력 하나와 `02-reference/output-contract.txt`를 함께 사용해
   입·출력 규격을 검토합니다.
5. 슬라이드 16에서 Claude 또는 ChatGPT의 새 대화를 열고, 결과 작성 기준 파일(output-contract.txt)과
   정상 입력 하나를 함께 첨부합니다. 첫 번째는 N-01-top10-api-snapshot.txt(표 형식), 두 번째는
   N-02-top10-text-list.txt(텔레그램 채널 요약 형식)를 사용합니다. 두 파일은 같은 날짜·같은 종목
   구성을 다른 형식으로 옮긴 것입니다.
6. **강의 자료의 V0 반복 시험 프롬프트를 기본으로** 사용합니다. 이 폴더의
   repetition-test-prompt.txt는 일반 채팅으로 시험할 때 쓸 동일한 보조 프롬프트입니다.
7. 받은 Top10 정리·상승 이유 요약·게시 초안은 `업무자동화/03-output/N-01-result.md`,
   `업무자동화/03-output/N-02-result.md`로 저장하고, 비교 기록은 `tests/lesson-02-results.md`에
   남깁니다.
8. expected-results.txt와 비교해 같은 여섯 heading을 썼는지, 필터링·분량·근거·확인 필요 표시가
   맞는지 확인합니다.
9. 실제 게시(배포)를 연습할 때만 publish-checklist.txt를 엽니다. 이 프로젝트의 실제 설계는
   "게시까지 자동, 그 뒤 사후 검토"이지만, 이 연습에서는 안전을 위해 실제 `git push`나 배포를
   실행하지 않고, 체크리스트 항목을 모두 사람이 확인했는지까지만 진행합니다.

중요한 경계
- 한 번의 대화에는 결과 작성 기준 파일(output-contract.txt)과 정상 입력 하나만 첨부합니다.
- virtual-lesson-01-roadmap.html과 virtual-lesson-01-roadmap.md는 가상 준비물입니다. 실제 증거가
  생기기 전에는 개인 로드맵을 완료로 바꾸지 않습니다.
- 첨부한 두 파일과 이 대화에 보이는 텍스트만 근거로 사용합니다.
- 게시 초안은 실제 게시(배포) 전 단계입니다. Top10 필터링·분량·근거·확인 필요가 모두 확인되고 사람이
  명시적으로 결정하기 전에는 실제 게시를 실행하지 않고 `게시 보류`로 기록합니다.
- 원시 자료에 없는 수치, 종목, 상승 이유는 채우지 말고 확인 필요로 표시합니다.

두 입력을 모두 같은 프롬프트로 처리한 뒤에만 결과 형식과 사실이 입력에 맞는지를 비교합니다.
개인·회사 원본(실제 API 응답 등)을 넣기 전 리허설용으로 쓰며, 실제 업무에 쓸 때는 승인된 기준과
사람 검토를 추가해야 합니다.
