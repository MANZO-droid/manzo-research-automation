# 가상 1강 산출물 · 당일 상승률 Top10 종목 분석 자동화

이 문서는 1강을 들었다고 가정하고 2강의 공통 실습을 시작할 때 쓰는 **가상 준비물**입니다.
개인 업무의 완료 기록이 아니므로, 실제 증거 없이 내 로드맵의 상태를 `완료`로 바꾸지 않습니다.
개인 자료를 준비하면 이 문서의 구조만 참고하고 내 업무의 사실로 교체하세요.

## 1. 1강 자동화 설계도 요약

| 설계 항목 | 가상 수업용 결정                                                                                                                                   |
| --------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| 업무      | 당일(또는 주간) 상승률 상위 종목 원시 자료를 Top10으로 정리하고, 상승 이유를 요약해 홈페이지 게시 초안으로 만듭니다.                               |
| 시작 신호 | `N-01-top10-api-snapshot.txt` 또는 `N-02-top10-text-list.txt` 한 건을 새 대화에 첨부합니다.                                                        |
| 입력 경계 | 첨부한 정상 입력 한 건과 결과 작성 기준 파일(`output-contract.txt`)에 적힌 내용만 근거로 씁니다.                                                   |
| AI 역할   | 원시 자료에서 우선주·관리종목·ETF·정리매매를 제외해 Top10을 정리하고, 상승 이유 요약과 게시 초안을 Markdown으로 만듭니다.                          |
| 반복 순서 | 원시 자료를 읽고 근거 있는 사실을 가릅니다. 여섯 heading에 맞춰 정리한 뒤 확인 필요·게시 초안을 남기고 검토를 기다립니다.                          |
| 결과물    | `03-output/N-01-result.md` 또는 `03-output/N-02-result.md`에 옮길 수 있는 초안과, 사람이 확인한 게시 보류 또는 게시 결과입니다.                   |
| 사람 검토 | 필터링·상승 이유 분량·근거가 원문에 있는지, 게시 여부를 사람이 확인했는지, 게시 후 오류 발견 시 수정·재게시 지시가 남았는지 확인합니다.            |
| 성공 기준 | 형태가 다른 N-01과 N-02가 같은 결과 작성 기준과 중단 조건을 지킵니다.                                                                              |
| 중단 조건 | 원시 자료에 없는 사실을 채워야 하거나, 필터링 후 Top10이 10개 미만이거나, 사람의 게시 확인 없이 실제 게시가 필요하면 게시 보류로 기록합니다.       |
| 증거      | `tests/lesson-02-results.md`에 두 결과를 비교한 내용과 한 번 수정했는지를 남깁니다.                                                                |

## 2. 2강에 가져올 다음 최소 단위

**다음 최소 단위:** 하나의 공통 프롬프트와 결과 작성 기준 파일(`output-contract.txt`)로 형식이 다른
정상 입력 두 건을 각각 새 대화에서 처리해, 같은 여섯 heading으로 Top10 정리·상승 이유 요약·게시
초안을 만들고, 우선주·관리종목·ETF·정리매매 제외가 두 입력에서 같은 결과로 나오는지 확인합니다.

| 2강 준비물     | 가상 실습에서 쓰는 것             | 할 일                                                             |
| -------------- | ---------------------------------- | ------------------------------------------------------------------ |
| 1강 설계도     | 위 표의 설계도 요약                | 개인 업무를 새로 고르지 않고 이 결정만 출발점으로 삼습니다.       |
| 1강 로드맵     | 아래 4회차 로드맵                  | 오늘의 상태는 `진행 전`에서 시작합니다.                           |
| 정상 입력 1    | `N-01-top10-api-snapshot.txt`      | 표 형식 원시 자료를 첫 번째로 시험합니다.                         |
| 정상 입력 2    | `N-02-top10-text-list.txt`         | 텔레그램 채널 요약 형식 원시 자료를 두 번째로 시험합니다.         |
| 결과 작성 기준 | `output-contract.txt`              | 두 번 모두 같은 여섯 heading과 Top10 표를 사용합니다.             |
| 공통 실행 지시 | `repetition-test-prompt.txt`       | 입력마다 바꾸지 않고 전문을 그대로 사용합니다.                     |
| 게시 전 확인   | `publish-checklist.txt`            | 필터링·분량·근거·확인 필요를 모두 확인한 뒤에만 게시 결정합니다.  |

## 4. 2강 실행 전 확인

1. 이 문서에서 **다음 최소 단위**와 중단 조건을 먼저 읽습니다.
2. 새 대화마다 결과 작성 기준 파일(`output-contract.txt`)과 정상 입력 **한 건만** 첨부합니다.
3. `repetition-test-prompt.txt`를 N-01과 N-02에 똑같이 사용합니다.
4. 두 초안을 `expected-results.txt`와 비교하고, 사람 검토 뒤에만 결과 파일로 저장합니다.
5. 게시는 초안까지만 만든 뒤, `publish-checklist.txt`의 필터링·분량·근거·확인 필요 항목이 모두
   확인된 경우에만 사람이 게시 여부를 결정합니다. 하나라도 없으면 게시 보류 이유를 기록합니다. 이
   연습에서는 실제 `git push`나 배포, 그 밖의 외부 발송·삭제·결제·권한 변경은 실행하거나 약속하지
   않습니다.
6. 실행 기록이나 승인된 원본 식별 규칙에서 N-01 또는 N-02와 같은 원본이 다시 들어온 것으로 확인되면,
   중복 입력으로 중단합니다. 새 결과·게시 초안·외부 행동·정상 완료 기록을 만들지 않고, 중단 사실만
   시험 기록으로 남깁니다. `목 입력 생성`으로
   정상·중복 입력 쌍을 만들어 중단 경계를 다시 시험합니다.

이 가상 준비물은 개인·회사 원본(실제 API 응답 등)을 넣기 전의 리허설용입니다. 실제 업무로 전환할
때에는 승인된 기준과 사람 검토 지점을 내 설계도와 로드맵에 다시 적으세요.
